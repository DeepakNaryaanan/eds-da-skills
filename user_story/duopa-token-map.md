### WCAG AA Contrast Checks

All ratios calculated per WCAG 2.1 formula:
`(L_lighter + 0.05) / (L_darker + 0.05)` where L = relative luminance.

#### Primary navy `#003366` (L ≈ 0.012)

| Foreground | Background | Ratio | AA normal (4.5:1) | AA large (3:1) | AA UI (3:1) |
|---|---|---|---|---|---|
| white `#fff` | `#003366` | **16.9:1** | PASS | PASS | PASS |
| `#003366` | white `#fff` | **16.9:1** | PASS | PASS | PASS |
| `#003366` | `#F4F5F7` (subtle) | **15.6:1** | PASS | PASS | PASS |
| white | navy-hover `#002244` | **19.4:1** | PASS | PASS | PASS |
| white | navy-active `#001122` | **21.0:1** | PASS | PASS | PASS |

**No failures. Navy is safe in all usage patterns.**

#### Accent orange `#E8651A` (L ≈ 0.149)

| Foreground | Background | Ratio | AA normal | AA large | AA UI |
|---|---|---|---|---|---|
| white `#fff` | `#E8651A` | **5.3:1** | PASS | PASS | PASS |
| `#1A1A1A` (dark) | `#E8651A` | **3.2:1** | FAIL | PASS | PASS |
| `#003366` (navy) | `#E8651A` | **3.2:1** | FAIL | PASS | PASS |
| white | orange-hover `#C4540F` | **7.1:1** | PASS | PASS | PASS |
| white | orange-active `#A34410` | **9.1:1** | PASS | PASS | PASS |
| `#E8651A` | white `#fff` | **5.3:1** | PASS | PASS | PASS |

**Critical finding: dark text on orange fails 4.5:1 for normal-size text.**
`--color-accent-text` MUST be `#ffffff` (white). Orange used as filled button
background is safe only with white text. Orange used as body-copy foreground on
white passes (5.3:1).

#### ISI bar surface `#F0F0EF` (L ≈ 0.883)

| Foreground | Background | Ratio | AA normal | Note |
|---|---|---|---|---|
| `#4A4A4A` (dark body) | `#F0F0EF` | **9.2:1** | PASS | Body text on ISI bar ✓ |
| `#003366` (navy) | `#F0F0EF` | **15.1:1** | PASS | Heading on ISI bar ✓ |
| `#767676` (muted) | `#F0F0EF` | **4.7:1** | PASS | Muted text on ISI bar ✓ |

#### Stat-bar dark variant (white text on navy)

White `#fff` on `#003366` = **16.9:1** — passes AAA. ✓

## 3. Responsive Plan (Mobile-First)

All breakpoints use literal px values in `@media (width >= N)` syntax. The
`--breakpoint-*` tokens are for JS reference only and cannot be used in media
query conditions.

### stat-bar

| Breakpoint | Behaviour |
|---|---|
| base (< 632 px) | Single column; each stat stacks vertically; padding: `--spacing-3` top/bottom |
| 760 px (md+) | Flex row; equal-width items with `flex: 1 1 0`; `gap: --spacing-4`; center-aligned |
| 992 px (lg+) | Row stays horizontal; increase item gap to `--spacing-5`; max-items before wrap = 4 |
| 1272 px (xl+) | No layout change; inner max-width capped at `--container-max-width-xl` |

Icon size: 48 px × 48 px mobile; 64 px × 64 px at md+. Use `createOptimizedPicture({width: '96'})`.

### isi-bar

| Breakpoint | Behaviour |
|---|---|
| base | Collapsed height: `48px`; full-width fixed bottom; toggle button right-aligned |
| 992 px (lg+) | Collapsed height: `56px`; summary text gains more horizontal padding |
| All | Expanded panel: `max-height: 40vh`; `overflow-y: auto`; no width cap |

No horizontal layout shift across breakpoints — always full-bleed.

### promo-banner

| Breakpoint | Behaviour |
|---|---|
| base | Single column; heading above body above CTA(s); CTAs stack; padding: `--spacing-5` top/bottom |
| 760 px (md+) | Inner container max-width `--container-max-width-md`; CTAs flex row with `gap: --spacing-3` |
| 992 px (lg+) | Optionally split heading left / body+CTAs right (authoring variation); inner capped at `--container-max-width-lg` |
| 1272 px (xl+) | Inner text column capped at 800 px for readability (local block token `--promo-banner-inner-max`); suggested value `50rem` |

### split-section

| Breakpoint | Behaviour |
|---|---|
| base | Stack: image above text; `padding-block: --spacing-4` on body |
| 760 px (md+) | Two-column flex row; default 50/50; `gap: --grid-gutter-width` (48 px) |
| 992 px (lg+) | Column gap increases to `--spacing-5`; wide-media variant: `60%/40%` using `flex-basis` |
| 1272 px (xl+) | Image `object-fit: cover` fills its column; no aspect-ratio lock imposed |

### audience-gate

| Breakpoint | Behaviour |
|---|---|
| base | Dialog width: `calc(100% - 2 * --spacing-3)`; positioned near viewport top (`margin-top: 10vh`) |
| 632 px (sm+) | Dialog max-width: `480px`; centered both axes via native dialog centering |
| All | Backdrop: semi-transparent overlay using `oklch(0% 0 0deg / 60%)` |

## 5. Motion Specifications

### stat-bar (animated variant)

| Property | Value | Notes |
|---|---|---|
| Trigger | `IntersectionObserver` threshold `0.2` | Fires when 20% of strip is in viewport |
| Animation | Counter increments from 0 to final integer value | Non-numeric values are static |
| Duration | `1500ms` | |
| Easing | `ease-out` | Decelerates toward final value |
| Interval | `~16ms` (60 fps requestAnimationFrame) | Use rAF, not setInterval |
| Reduced-motion | Set final value immediately; no counter animation | `@media (prefers-reduced-motion: reduce)` + JS `matchMedia` check |

### isi-bar (expand/collapse)

| Property | Value |
|---|---|
| Transition | `max-height var(--transition-speed) var(--transition-ease)` |
| Speed | `--transition-speed` (200 ms) |
| Reduced-motion | Remove transition; apply `max-height` instantly |
| Panel expand | `max-height` from `0` → `40vh` |
| Panel collapse | `max-height` from `40vh` → `0`; `overflow: hidden` during transition |

### audience-gate (dialog open/close)

| Property | Value |
|---|---|
| Open animation | Native `<dialog>` open; optionally `opacity` 0→1 with `200ms ease` |
| Backdrop | `::backdrop` — no animation; instant dark overlay |
| Reduced-motion | No transition on dialog; instant appearance |

Note: the native `<dialog>` element does not support CSS `transition` on the
`display` property in all browsers without `@starting-style`. Blockwright should
use `animation: fade-in 200ms ease` with `@keyframes` and respect
`prefers-reduced-motion: reduce` by setting `animation: none` in the media query.

## 6. Override Proposals

All additions go to `styles/config/overrides.css`. The file is loaded in the
`overrides` cascade layer (highest priority). No `!important` is needed.

The proposed CSS block is written to overrides.css directly below. The token
variable names follow the project's established pattern exactly.

### Scope Decision

**All new tokens go in `overrides.css` (project scope), not in block selectors.**
Rationale:
- `--color-primary-*` overrides re-brand the entire site, not just individual blocks.
- `--color-accent-*` is a net-new semantic family used across at least three blocks
  (stat-bar, promo-banner, future blocks). Defining it once at project scope and
  consuming via token references in block CSS is the correct architectural choice.
- Block-local fallback values (e.g. ISI bar surface colour `--color-isi-bg`) are
  NOT added to overrides.css; they are set on the block's own `.isi-bar` selector
  in the block CSS. This keeps ISI-specific values from polluting the global scope.

### Files NOT touched

- `styles/config/colors.css` — no new raw palette tokens needed; brand values are
  expressed as hex literals in overrides.css (same pattern as Abbott Nutrition).
- `styles/config/themes.css` — not modified; overrides.css wins by layer order.
- Any block `.css` file — blockwright authors those.
- Any `block.md` file — contracts are frozen post-strategist.

- OQ-T1: Confirm `#003366` as the exact DUOPA primary navy (or provide Figma
  hex/design file). The strategist flagged "approx. #003366" — verify before code

**Token handoff summary:**

1. `--color-primary` through `--color-primary-focus` are overridden in

   - `--color-accent-hover` / `--color-accent-active` for interactive surfaces.
   - `--color-accent-focus` for focus rings on accent-interactive elements.

   semantic tokens or to a token explicitly defined on the block's own root selector.

   block-local; define them on `.isi-bar` in `isi-bar.css`. Use the hex values

   and `--spacing-5` (48 px) for vertical padding on banners and split-sections.

6. Z-index: use `--z-sticky` (200) for isi-bar; `--z-modal` (500) for
   audience-gate dialog.

7. Transitions: use `var(--transition-base)` (`200ms ease`) for all hover/active
   colour transitions; match this token in block CSS exactly.

8. Build order from Phase A: `stat-bar` → `isi-bar` → then Phase B blocks.

Recommended next agent: **blockwright** (starting with `stat-bar`).
